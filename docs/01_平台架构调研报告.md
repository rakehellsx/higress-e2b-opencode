# 基于 Higress、OpenCode 和 E2B 构建大模型网关与类 Manus 智能体平台调研报告

## 1. 引言

随着大型语言模型（LLM）能力的不断提升，AI Agent（智能体）正从简单的聊天助手演变为能够执行复杂任务、自主规划并与外部环境交互的“数字员工”。Manus 作为新一代通用 AI Agent 的代表，展示了强大的任务执行能力。本文旨在调研 Higress、OpenCode 和 E2B 三个开源及商业项目，分析它们的核心能力，并探讨如何基于这三者构建一套大模型网关与类 Manus 智能体平台。

## 2. 核心组件分析

### 2.1 Higress：AI 原生大模型网关

Higress 是一款基于 Envoy 和 Istio 的云原生 API 网关，针对 AI 时代进行了深度演进 [1]。它在系统中扮演着“流量调度中心”和“能力集成中枢”的角色。Higress 能够将外部请求统一转发到后端的各种大模型（支持 100 多种主流模型及本地部署模型），屏蔽了不同厂商的 API 差异，实现统一的协议转换。同时，它支持多模型负载均衡和 Fallback 机制，保障服务的高可用性。

除了传统的 QPS 限流，Higress 还支持基于 Token 消耗的限流和配额管理。结合 API Key 轮转机制，这能有效控制成本并防止恶意滥用。此外，Higress 原生支持模型上下文协议（MCP），不仅能代理原生的 MCP 服务，还提供 openapi-to-mcp 工具，将传统的 RESTful OpenAPI 批量、零代码转换为 MCP Server。这使得 AI Agent 能够以标准化的方式调用各种企业内部工具和外部 API。Higress 还提供超过 40 个开箱即用的插件，包括语义缓存（降低 API 成本和延迟）、Prompt 注入检测、敏感数据脱敏、响应格式化（如强制 JSON 输出）等，极大简化了 AI 应用的开发和治理 [2]。

### 2.2 OpenCode：开源的终端与环境驱动 Agent

OpenCode 是一个专为终端和开发环境设计的开源 AI 编码 Agent [3]。在类 Manus 平台中，它主要承担“任务执行者（Executor）”的角色。OpenCode 采用 Primary Agents（如 Build、Plan）和 Subagents（如 Explore、General）的协同架构。Primary Agent 负责主流程对话和任务规划，而 Subagents 则被调用来执行特定的子任务（如代码搜索、文件分析），这种设计非常契合复杂任务的拆解与执行。

OpenCode 原生具备文件读写、Bash 命令执行等能力。更重要的是，它深度集成了 MCP 协议，支持接入本地和远程的 MCP Servers。通过 Higress 托管的 MCP 服务，OpenCode 可以轻松获取企业内外部的各种能力。此外，OpenCode 提供了基于 HTTP 的 Headless Server 模式和类型安全的 TypeScript/JavaScript SDK [4]。这使得外部系统（如我们构建的平台控制面）可以编排、监控和干预 OpenCode 的执行过程，实现更高级的自动化工作流。

### 2.3 E2B：企业级 AI Agent 安全沙箱

E2B 提供基于 Firecracker microVM 的安全、隔离的云端沙箱环境，是 AI Agent 能够“放开手脚”执行真实世界操作的基础设施 [5]。基于 Firecracker 技术，E2B 沙箱可以在约 150 毫秒内启动。与传统的 Docker 容器不同，它提供了一个完整的 Linux 操作系统环境，允许 Agent 执行安装软件包、运行后台服务等复杂操作 [6]。

E2B 支持长达 24 小时的持续运行，并提供沙箱持久化（Persistence）和快照功能。这使得 Agent 可以执行耗时较长的任务，并在需要人类介入（如扫码验证、输入密码）时暂停，随后恢复执行，保持上下文不丢失。E2B Desktop 模板提供了一个完整的 Ubuntu 桌面环境，并支持 VNC 实时流媒体传输。这使得 Agent 能够像人类一样操作图形界面应用程序（如浏览器），极大地扩展了 Agent 的能力边界。此外，E2B 官方提供了预装 OpenCode 的沙箱模板，开发者可以通过 E2B 快速拉起一个包含 OpenCode 运行时的隔离环境，确保代码执行和系统操作的安全性 [7]。

## 3. 类 Manus 平台架构设计

基于上述三个组件，我们可以构建一个具备强大规划、执行和资源管理能力的类 Manus 智能体平台。整体架构可划分为基础设施层、网关与控制面、智能体执行层以及交互与应用层。

| 架构层级 | 核心组件 | 主要职责 |
| :--- | :--- | :--- |
| **交互与应用层** | Web 终端/控制台、API 接口 | 提供用户界面，接收自然语言指令；展示 Agent 思考过程、终端输出、文件变更及 VNC 画面；允许外部系统触发任务。 |
| **智能体执行层** | OpenCode (Planner, Executor)、Computer User | 运行在沙箱内；Planner 负责任务拆解；Executor 利用沙箱工具和 MCP 执行任务；Computer User 执行图形界面操作。 |
| **网关与控制面** | Higress、任务编排与调度引擎 | Higress 负责 LLM 路由、鉴权、Token 限流、语义缓存及 MCP 服务托管；调度引擎负责分配沙箱资源、监控进度。 |
| **基础设施层** | E2B 沙箱集群、模型服务 | 提供隔离的物理执行环境（microVM）；提供各种商业及开源大模型服务。 |

## 4. 核心工作流推演

任务执行流程始于用户在 Web 控制台输入任务指令。调度引擎接收到请求后，通过 E2B API 毫秒级拉起一个包含 OpenCode 运行时的沙箱实例。沙箱启动后，调度引擎通过 OpenCode SDK 初始化会话，并将任务目标和环境上下文（如可用的 MCP 工具列表，该列表由 Higress 提供）注入给 OpenCode 的 Planner Agent。

Planner Agent 分析任务并生成执行计划。随后进入循环执行阶段：Executor Agent 根据计划逐步执行。如果需要查询外部数据或操作内部系统，Executor 构造 MCP 请求发送给 Higress。Higress 验证请求，将其路由到对应的 LLM 或后端服务，并执行缓存、限流等策略，然后返回结果。如果需要执行代码或命令行，Executor 直接在 E2B 沙箱内运行，获取标准输出和错误信息。

在执行过程中，OpenCode 通过其 Headless Server 的事件机制，将执行的每一步状态（思考、工具调用、结果）实时推送给调度引擎，最终展示在用户的 Web 控制台上。任务完成后，系统汇总结果输出给用户。调度引擎根据策略决定是保留沙箱状态（用于后续追问）还是销毁沙箱释放资源。

## 5. 平台价值与优势

通过整合 Higress、OpenCode 和 E2B，构建的平台具有显著的系统价值和技术优势。首先是极高的安全性与隔离性，E2B 的 microVM 架构确保了 Agent 执行未知或生成的代码时，不会对宿主机和其他租户造成威胁。其次是强大的扩展能力，借助 Higress 的 MCP 托管能力，平台可以轻松接入成千上万的企业内部 API 和外部 SaaS 服务，极大地丰富了 Agent 的工具库。

在企业级治理与成本控制方面，Higress 提供了细粒度的 Token 限流、多模型路由和缓存机制。这不仅有效控制了大模型调用的高昂成本，还保障了服务的稳定性。最后，在灵活的智能体编排方面，OpenCode 提供了成熟的多智能体协同框架和 SDK，支持从简单的代码生成到复杂的长周期任务自动化。这种融合了智能生成与人工编排策略的架构，充分体现了系统的长期价值和扩展潜力。

## 6. 结论

Higress 提供了卓越的 AI 流量治理和工具（MCP）集成能力，OpenCode 提供了灵活且强大的 Agent 运行时架构，而 E2B 提供了安全可靠的底层执行沙箱。将这三者结合，不仅在技术架构上高度互补，而且能够快速构建出一个功能完备、安全可控、具备企业级治理能力的类 Manus 通用智能体平台，为自动化办公、研发辅助和复杂任务处理提供强大的基础设施支撑。
